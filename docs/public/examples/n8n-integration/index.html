n8n Integration

n8n Integration with Focus Helper

This guide shows how to integrate Focus Helper with n8n, a powerful workflow automation tool, to create sophisticated focus management workflows.

Overview

n8n allows you to create complex workflows that can:

  • Monitor focus sessions in real-time
  • Send notifications to multiple channels
  • Trigger actions based on focus patterns
  • Integrate with external services
  • Create custom dashboards

Prerequisites

  • n8n installed (Docker, npm, or self-hosted)
  • Focus Helper running with MCP server enabled
  • Basic n8n knowledge

Setup

1. Start Focus Helper with MCP

1focushelper --mcp --docker

2. Install n8n

Using Docker (Recommended)

1docker run -it --rm --name n8n -p 5678:5678 -v ~/.n8n:/home/node/.n8n n8nio/n8n

Using npm

1npm install n8n -g
2n8n start

3. Access n8n

Open your browser and go to http://localhost:5678

Create a workflow that monitors focus sessions and sends notifications.

11    "params": {}
12  }
13}

IF Node (Check if active):

1// Expression
2{{ $json.result.is_active === true }}

Switch Node (Duration check):

1// Route 1: Short session (< 30 minutes)
2{{ $json.result.duration && $json.result.duration.includes('m') && parseInt($json.result.duration) < 30 }}
3
4// Route 2: Medium session (30-60 minutes)
5{{ $json.result.duration && ($json.result.duration.includes('h') || parseInt($json.result.duration) >= 30) }}
6
7// Route 3: Long session (> 1 hour)
8{{ $json.result.duration && $json.result.duration.includes('h') && parseInt($json.result.duration.split('h')[0]) > 1 }}

3. Break Reminder System

Create an automated break reminder system.

Workflow Steps:

  1. Cron Trigger - Run every 15 minutes
  2. HTTP Request - Get session info
  3. Function Node - Calculate break need
  4. Switch Node - Route based on break urgency
  5. Multiple Action Nodes - Send reminders

Configuration:

Function Node (Calculate break need):

 1const session = $input.first().json.result;
 2const duration = session.duration;
 3
 4// Parse duration to minutes
 5let minutes = 0;
 6if (duration.includes('h')) {
 7  const hours = parseInt(duration.split('h')[0]);
 8  minutes += hours * 60;
 9}
10if (duration.includes('m')) {
11  const mins = parseInt(duration.match(/(\d+)m/)?.[1] || 0);
12  minutes += mins;
13}
14
15// Determine break urgency
16let breakUrgency = 'none';
17if (minutes > 240) { // 4 hours
18  breakUrgency = 'critical';
19} else if (minutes > 120) { // 2 hours
20  breakUrgency = 'high';
21} else if (minutes > 60) { // 1 hour
22  breakUrgency = 'medium';
23} else if (minutes > 30) { // 30 minutes
24  breakUrgency = 'low';
25}
26
27return {
28  json: {
29    ...session,
30    durationMinutes: minutes,
31    breakUrgency: breakUrgency,
32    needsBreak: breakUrgency !== 'none'
33  }
34};

2. Focus Analytics Dashboard

Create a dashboard that tracks focus patterns over time.

Workflow Steps:

  1. Cron Trigger - Every hour
  2. HTTP Request - Get session info
  3. Function Node - Process data
  4. Google Sheets Node - Store data
  5. Webhook Node - Update dashboard

Configuration:

Function Node (Process analytics):

 1const session = $input.first().json.result;
 2const now = new Date();
 3
 4// Calculate session metrics
 5const duration = session.duration;
 6const isActive = session.is_active;
 7const hyperfocus = session.hyperfocus_level;
 8
 9// Parse duration to minutes
10let minutes = 0;
11if (duration.includes('h')) {
12  minutes += parseInt(duration.split('h')[0]) * 60;
13}
14if (duration.includes('m')) {
15  minutes += parseInt(duration.match(/(\d+)m/)?.[1] || 0);
16}
17
18// Calculate productivity score
19let productivityScore = 0;
20if (isActive) {
21  productivityScore = Math.min(minutes / 60, 8); // Max 8 hours
22}
23
24// Determine focus quality
25let focusQuality = 'normal';
26if (hyperfocus === 'critical') {
27  focusQuality = 'unhealthy';
28} else if (hyperfocus === 'high') {
29  focusQuality = 'intense';
30} else if (hyperfocus === 'medium') {
31  focusQuality = 'good';
32} else if (hyperfocus === 'low') {
33  focusQuality = 'light';
34}
35
36return {
37  json: {
38    timestamp: now.toISOString(),
39    date: now.toISOString().split('T')[0],
40    hour: now.getHours(),
41    duration: duration,
42    durationMinutes: minutes,
43    isActive: isActive,
44    hyperfocus: hyperfocus,
45    focusQuality: focusQuality,
46    productivityScore: productivityScore,
47    subject: session.subject || 'Unknown'
48  }
49};

3. Smart Break Scheduler

Create an intelligent break scheduler that adapts to focus patterns.

Workflow Steps:

  1. Cron Trigger - Every 5 minutes
  2. HTTP Request - Get session info
  3. Function Node - Calculate break timing
  4. Switch Node - Route based on break need
  5. HTTP Request - Trigger appropriate alert
  6. Calendar Node - Schedule break time

Configuration:

Function Node (Smart break calculation):

 1const session = $input.first().json.result;
 2const duration = session.duration;
 3const hyperfocus = session.hyperfocus_level;
 4
 5// Parse duration
 6let minutes = 0;
 7if (duration.includes('h')) {
 8  minutes += parseInt(duration.split('h')[0]) * 60;
 9}
10if (duration.includes('m')) {
11  minutes += parseInt(duration.match(/(\d+)m/)?.[1] || 0);
12}
13
14// Calculate break recommendations
15let breakRecommendation = null;
16let alertLevel = -1;
17
18if (minutes > 240) { // 4+ hours
19  breakRecommendation = {
20    type: 'emergency',
21    duration: 30,
22    message: 'Emergency break needed - 30 minutes recommended'
23  };
24  alertLevel = 3; // Critical
25} else if (minutes > 120) { // 2+ hours
26  breakRecommendation = {
27    type: 'extended',
28    duration: 20,
29    message: 'Extended break recommended - 20 minutes'
30  };
31  alertLevel = 2; // High
32} else if (minutes > 60) { // 1+ hour
33  breakRecommendation = {
34    type: 'standard',
35    duration: 15,
36    message: 'Standard break recommended - 15 minutes'
37  };
38  alertLevel = 1; // Medium
39} else if (minutes > 30) { // 30+ minutes
40  breakRecommendation = {
41    type: 'micro',
42    duration: 5,
43    message: 'Micro break recommended - 5 minutes'
44  };
45  alertLevel = 0; // Low
46}
47
48// Adjust based on hyperfocus level
49if (hyperfocus === 'critical') {
50  breakRecommendation.duration = Math.max(breakRecommendation.duration, 30);
51  breakRecommendation.message += ' (Critical hyperfocus detected)';
52} else if (hyperfocus === 'high') {
53  breakRecommendation.duration = Math.max(breakRecommendation.duration, 20);
54  breakRecommendation.message += ' (High hyperfocus detected)';
55}
56
57return {
58  json: {
59    ...session,
60    durationMinutes: minutes,
61    breakRecommendation,
62    alertLevel,
63    shouldTriggerAlert: alertLevel >= 0
64  }
65};

Best Practices

1. Workflow Organization

  • Use descriptive names for workflows and nodes
  • Add comments to complex function nodes
  • Group related workflows in folders
  • Use consistent naming conventions

2. Error Handling

  • Always include error handling in workflows
  • Use try-catch blocks in function nodes
  • Set up error notifications for critical workflows
  • Test error scenarios regularly

3. Performance

  • Use appropriate trigger intervals (not too frequent)
  • Cache data when possible
  • Use parallel execution for independent operations
  • Monitor workflow execution times

4. Security

  • Use environment variables for sensitive data
  • Validate input data in function nodes
  • Use HTTPS for external API calls
  • Implement rate limiting for external services

Troubleshooting

Common Issues

  1. Connection Refused

    • Check if Focus Helper is running
    • Verify MCP server port (8089)
    • Check firewall settings

  2. Authentication Errors

    • Verify API keys and tokens
    • Check service permissions
    • Update expired credentials

  3. Workflow Execution Errors

    • Check node configurations
    • Verify data formats
    • Review error logs

  4. Performance Issues

    • Reduce trigger frequency
    • Optimize function node code
    • Check resource usage

Debug Tips

  1. Use Debug Mode in n8n
  2. Add logging in function nodes
  3. Test individual nodes before full workflow
  4. Monitor execution logs
  5. Use webhook nodes for testing
